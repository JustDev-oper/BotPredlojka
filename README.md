# Бот для приёма и публикации постов в Telegram-каналы

Реализация на **aiogram 3** + **aiosqlite** по техническому заданию.

## Установка

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

## Настройка

Откройте `config.py` и укажите:

- `BOT_TOKEN` — токен бота от @BotFather (можно также передать через переменную окружения `BOT_TOKEN`)
- `OWNER_ID` — уже прописан из ТЗ (`5877007064`), при необходимости замените

## Запуск

```bash
python3 main.py
```

База данных SQLite создаётся автоматически в файле `bot.db` (путь настраивается через `DB_PATH`).

## Структура проекта

```
config.py                    — настройки, ID владельца, лимиты антиспама и автоудаления
database.py                  — вся работа с SQLite (пользователи, каналы, посты, заявки, автоудаление и т.д.)
states.py                    — FSM-состояния для многошаговых сценариев
keyboards.py                 — все инлайн-клавиатуры
utils.py                     — вспомогательные функции (проверка подписки, отправка контента)
middlewares.py                — блокировка забаненных пользователей
scheduler.py                  — фоновая задача автоудаления постов по таймеру
main.py                       — точка входа, регистрация роутеров

handlers/
  user.py                     — /start, выбор канала, проверка подписки, приём поста, антиспам
  moderation.py                — карточка модерации, публикация/отклонение/бан, ответ через цитирование
  admin.py                     — /admin, статистика, фейк-статистика, бан-лист, пользователи, каналы,
                                  водянка, администраторы
  applications.py              — раздел «Заявки»
  broadcast_bot.py             — рассылка сообщения всем пользователям бота
  broadcast_channels.py        — рассылка поста по нескольким каналам (только владелец)
  autodelete.py                — управление автоудалением опубликованных постов
```

## Важные моменты реализации (из ТЗ)

- **Заявки не блокируют отправку поста** — как только пользователь нажал на канал (даже не подписавшись),
  ему открывается форма отправки поста после подтверждения подписки; заявка создаётся, но её принятие
  администратором не требуется для дальнейшей работы.
- **Антиспам** — не более 2 постов в час на пользователя (настраивается в `config.py`).
- **Водянка** добавляется только при публикации отдельных постов через модерацию и НИКОГДА при рассылке
  по каналам.
- **Рассылка по каналам** — доступна только владельцу (`OWNER_ID`), публикуется в silent-режиме, без
  предпросмотра ссылок и без водянки.
- **Автоудаление** активируется только в сценарии рассылки по каналам, перед отправкой поста админ выбирает
  таймер (2ч/24ч/48ч/72ч/не удалять). Фоновая задача `scheduler.py` каждые 30 секунд проверяет, какие посты
  пора удалить.
- **Ответ пользователю без отдельного чата** — администратор отвечает (Reply) прямо на карточку поста в
  боте, бот пересылает текст пользователю с пометкой «На ваш пост ответил модератор».
- **/rndadm** — восстанавливает права владельца, если они были случайно потеряны.

## Ограничения и что стоит доработать перед продакшеном

- Бот должен быть добавлен администратором во все каналы, которые планируется использовать
  (для проверки подписки, публикации и получения invite-ссылки).
- Проверка подписки использует `bot.get_chat_member` — для приватных каналов это работает только если бот
  сам является администратором канала.
- Для больших объёмов пользователей стоит заменить `asyncio.sleep(0.05)` в рассылке по боту на более точный
  расчёт под лимиты Telegram (~30 сообщений/сек).
- Фейковая статистика хранится как два отдельных числа (`users`, `posts`); при необходимости формат вывода
  в `fs:show` легко расширить под произвольный шаблон текста.
